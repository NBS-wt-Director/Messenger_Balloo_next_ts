| Тип | Пример | Когда |
|-----|--------|-------|
| **Major (1.x.x → 2.x.x)** | Изменение архитектуры | По решению архитектора |
| **Minor (1.0.x → 1.1.x)** | Добавление фич | По согласованию |
| **Patch (1.0.0 → 1.0.1)** | Исправление опечаток | По факту обнаружения |

## 🔄 ПРОЦЕСС ИЗМЕНЕНИЯ ТРЕБОВАНИЙ

### Инициирование изменения

```yaml
Кто: Любой участник проекта
Как: GitHub Issue с меткой "requirement-change"
Что указать:
  - Какой документ изменить
  - Какое требование изменить
  - Обоснование изменения
  - Влияние на другие компоненты
```

### Рассмотрение изменения

```yaml
Кто: Архитектор + ответственные команды
Срок: 3 рабочих дня
Решение:
  - ✅ Принято → обновить документ, увеличить версию
  - 🟡 Принято с правками → обновить с учётом правок
  - ❌ Отклонено → закрыть issue с комментарием
```

### Реализация изменения

```yaml
Кто: Исполнители по задаче
Что:
  - Обновить проектную документацию
  - Обновить код (если требуется)
  - Обновить отчётную документацию (факт выполнения)
  - Добавить запись в CHANGELOG
```
