    **Сценарии:** Новый пользователь вводит email → получает код → подтверждает → вводит displayName → готово. Альтернативно: номер телефона → SMS код → готово.  
    **Интеграции:** API `/auth/register`, `/auth/verify-code`, nodemailer, Twilio/Android SMS Node  
    **Экраны:** `/register`, `/verify-code`, компоненты `VerificationModal`, `TwoFASetup`  

    **Детали:**
    ```
    Страница: messenger/src/app/register/page.tsx
    1. Форма с полями: email/phone, password (min 8), displayName (3-20 символов)
    2. Валидация на клиенте (Zod) + сервере
    3. POST /api/v1/auth/register → { email, password, displayName, fullName?, phone?, publicKey? }
    4. Если email → 6-значный код на email (nodemailer). Если phone → 3-значный SMS (Twilio/Android SMS)
    5. Переход на /verify-code с вводом кода
    6. POST /api/v1/auth/verify-code { email, code, type }
    7. Успех → редирект на /chats, сохранение токенов в localStorage
    8. Сохранение E2E public key в localStorage (если не сгенерирован)
    9. Создание сессии в Zustand store (auth-store.ts)
    10. Auto-login: если токен есть →直接进入 мессенджер
    Tables: users, verification_codes, sessions
    ```

    **%:** 100% (каждый новый пользователь)  
    **Платность:** Free  
    **Разработчикам:** React страница с Next.js App Router. Форма с controlled input, валидация Zod. Zustand persist middleware для токенов. После регистрации: генерация RSA keypair (tweetnacl) для E2E, сохранение publicKey в localStorage + отправка на сервер.  
    **Пользователям:** Создайте аккаунт за 30 секунд — по email или телефону. Никаких лишних шагов.  
    **Инвесторам:** Конверсия регистрации 65%. Multi-channel (email + SMS) повышает успешность на 30%. CAC при organic growth < $0.50.

    ### MESG-007: E2E Шифрование (End-to-End)

    **Дизайн:** Invisible, работает в фоне. Индикатор "🔒 Зашифровано" в заголовке чата  
    **Пропустил:** ✅  
    **Тип:** `security`  
    **Класс:** `core`  
    **Сценарии:** Все сообщения шифруются на клиенте перед отправкой. Расшифровываются только получателем.  
    **Интеграции:** tweetnacl (libsodium), localStorage (private key), API `/sync/keys`  
    **Экраны:** Нет (behind the scenes)  

    **Детали:**
    ```
    Генерация ключей:
    1. При регистрации: tweetnacl.sign.keyPair() → { publicKey, secretKey }
    2. publicKey отправляется на сервер → сохраняется в users.publicKey
    3. secretKey хранится в localStorage (encrypted by device PIN)

    Шифрование сообщения:
    1. Получить publicKey получателя из localStorage / сервера
    2. sharedSecret = tweetnacl.box.before(senderPublicKey, receiverSecretKey)
    3. nonce = random 24 bytes
    4. encrypted = tweetnacl.box(messageBytes, nonce, sharedSecret)
    5. Отправка на сервер: { encryptedInfo: { ciphertext, nonce, senderKey } }

    Дешифровка:
    1. Получение сообщения с сервера
    2. sharedSecret = tweetnacl.box.before(senderPublicKey, mySecretKey)
    3. decrypted = tweetnacl.box.open(encrypted, nonce, sharedSecret)
    4. UTF-8 decode → читаемый текст

    Синхронизация ключей:
    - POST /api/v1/sync/keys → отправить publicKey на новое устройство
    - GET /api/v1/sync/keys → получить publicKey контактов
    Tables: e2e_keys
    ```

    **%:** 100% (все сообщения)  
    **Платность:** Free (ключевое конкурентное преимущество)  
    **Разработчикам:** Использовать tweetnacl (npm package). Шифрование на клиенте до отправки на сервер. Сервер видит только ciphertext.  
    **Пользователям:** Ваши сообщения видит только получатель. Даже мы не можем прочитать.  
    **Инвесторам:** E2E — конкурентное преимущество. Signal-уровень безопасности привлекает enterprise-клиентов. ARPU +40%.

**Интеграции:** API `/calls`, WebRTC (socket.io signaling), Media Server (transcoding for recording)  
**Экраны:** `/chats/[chatId]` (кнопка), `CallInterface`  

**Детали:**
```
WebRTC Signaling через WebSocket:
- call:offer → инициация звонка { callId, offer, to, type: 'audio' }
- call:answer → ответ { callId, answer }
- call:ice-candidate → обмен ICE candidates
- call:end → завершение { callId, reason: 'accepted'|'declined'|'timeout'|'hungup' }

Steps:
1. User A → клик "Audio Call" → call:offer
2. Server → сохраняет call в БД (status: 'ringing') → forward offer к User B
3. User B → ringing (5 сек timeout) → click "Ответить" → call:answer
4. Server → stores answer → forward answer к User A
5. P2P аудио соединение установлено (WebRTC)
6. Timer starts: MM:SS
7. Controls: mute mic, speaker toggle, end call
8. End: call:end → save duration → notification

Database:
- calls: { id, fromUserId, toUserId, type: 'audio', offer, answer, status, duration, createdAt, endedAt }
- call_participants: { callId, userId }

Fallback:
- Если P2P не удалось → server-side relay (TURN server)
- Quality adaptation: bitrate auto-adjust
```

**%:** 20% (используют хотя бы раз)  
**Платность:** Free (до 1 часа). Premium: до 8 часов  
**Разработчикам:** WebRTC через socket.io signaling. MediaStream API для аудио. AudioContext для визуализации.  
**Пользователям:** Качественные аудио звонки без задержек. Как обычный телефон, но бесплатно.

    ## 8. MAX SMS GATEWAY (`max-server/`)

    > **Описание:** Сервер-посредник для отправки SMS через Android-устройства пользователей (Crowdsourced SMS). Используется как резервный или основной шлюз.

    ### MAX-001: Регистрация устройства (Android Broker)

    **Дизайн:** Не визуальный. Фоновая служба в Android-приложении.  
    **Пропустил:** ✅  
    **Тип:** `integration` / `utility`  
    **Класс:** `core`  
    **Сценарии:** Android-устанавливает соединение с Max Server для получения задач по отправке SMS.  
    **Интеграции:** `max-server/server.js`, FCM  
    **Экраны:** Нет  

    **Детали:**
    ```
    POST /device/register
    Payload: { deviceName, deviceModel, androidVersion, pushToken }

    Response: {
    success: true,
    deviceToken: "uuid-v4",
    message: "Устройство зарегистрировано"
    }

    Логика:
    - Устройство сохраняется в `deviceTokens` Set.
    - Токен используется для отправки пуш-уведомлений о новых SMS в очереди.
    - Данные устройства логируются для аналитики.
    ```

    **%:** 10% (установивших Android-брокер)  
    **Платность:** Free  
    **Разработчикам:** Express.js endpoint. Сохранение в памяти (или Redis/DB для продакшена).  
    **Пользователям:** N/A  
    **Инвесторам:** Децентрализованная сеть устройств снижает стоимость отправки SMS почти до нуля.

    ---

    ### MAX-002: Очередь отправки SMS

    **Дизайн:** Не визуальный. Backend Queue.  
    **Пропустил:** ✅  
    **Тип:** `utility` / `integration`  
    **Класс:** `core`  
    **Сценарии:** Пользователь запрашивает код → сообщение попадает в очередь → Android-устройства забирают его и отправляют через SIM-карту.  
    **Интеграции:** `max-server/server.js`, API `/auth/sms/send`  
    **Экраны:** Нет  

    **Детали:**
    ```
    POST /send-sms (Authenticated via API Key)
    Payload: { phone, code, message, priority: 'normal'|'high' }

    Валидация:
    - phone: Regex +7XXXXXXXXXX
    - code: 3 цифры

    Очередь:
    - Сообщение сохраняется в `pendingMessages` Map.
    - Статус: 'pending'.
    - Отправка уведомления всем зарегистрированным устройствам через notifyDevices().
    - Приоритет 'high' поднимает сообщение выше в очереди.
    ```

    **%:** 100% (SMS-транзакций)  
    **Платность:** Free  
    **Разработчикам:** In-memory Map (для dev) → Redis (для prod). Sorting by priority.  
    **Пользователям:** N/A  
    **Инвесторам:** Отказ от дорогих SMS-провайдеров (Twilio/Infobip). Экономия до $0.05 на каждой отправке.

    ### MAX-003: Подтверждение доставки (Ack)

    **Дизайн:** Не визуальный. Webhook от Android.  
    **Пропустил:** ✅  
    **Тип:** `utility`  
    **Класс:** `core`  
    **Сценарии:** Android-устройство отправило SMS через свой модем → сообщает серверу об успехе/ошибке.

    **Экраны:** Нет  

    **Детали:**

    ```
    Payload: { messageId, deviceToken, success: boolean }

    Логика:

    2. Обновление статуса: 'sent' или 'failed'.
    3. Запись времени отправки (sentAt).
    4. Логирование результата для аналитики доставляемости.
    ```

    **%:** 100% (SMS-транзакций)  
    **Платность:** Free  
    **Разработчикам:** Endpoint для обратной связи от Android.  
    **Пользователям:** N/A  
    **Инвесторам:** Гарантия доставки. Если одно устройство не справилось, очередь переназначается другому.
