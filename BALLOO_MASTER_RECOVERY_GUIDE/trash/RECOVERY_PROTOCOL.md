### 📋 Алгоритм действий при запросе "почини BALLOO_MASTER_RECOVERY_GUIDE: ..."

При получении команды на исправление документации, агент обязан выполнить следующие шаги в строгом порядке:

1.  **Анализ запроса**
    *   Определить затронутый раздел (functions, nodes, screens, infra и т.д.).
    *   Выявить скрытые зависимости (изменения в БД влияют на API, изменения API влияют на Frontend).

2.  **Исправление документации (JSON-источники)**
    *   Обновить соответствующий файл в `steps/_json/[раздел]/data.json`.
    *   Если затронуты макеты (mockups) — перестроить HTML-код макета с учетом новых данных.
    *   Если затронуты функции — обновить статус реализации (✅/🟡/❌) и метаданные (версия, платность).

3.  **Создание новых разделов (при необходимости)**
    *   Если данных стало много, создать новую папку `_json/[новое_название]/` с `data.json`.
    *   Добавить навигацию в `20260626-1402.html`.

4.  **Cross-Check (Кросс-проверка)**
    *   Проверить, не "сломались" ли смежные разделы.
    *   *Пример:* Если поменяли порт API в `nodes`, проверить `functions` (эндпоинты) и `screens` (запросы).
    *   *Пример:* Если добавили новую сущность в БД, добавить эндпоинт в `functions` и экран в `screens`.

5.  **Финальная валидация**
    *   Убедиться, что HTML-интерфейс корректно рендерит новые данные.
    *   Проверить JSON-схемы на валидность.

### 🌍 Реальный контекст проекта (Hard Constraints)

*   **Домен:** `balloo.su` (Zones RU/SU)
*   **Сервер:** Физический сервер в Екатеринбурге (РФ).
*   **Правовое поле:** РФ (строгое соблюдение 152-ФЗ, 150-ФЗ "Яровая", ГОСТы).
*   **Архитектура:** Monorepo из нескольких узлов, объединённых кодовой базой. Каждый узел может подниматься на одном или более контейнерах на одном или более серверах в рамках одной виртуальной сети и одного workspace.
*   **Порты узлов (30**):** API Gateway:3001, Messenger:3002, Admin Portal:3003, Web App:3004, Mobile API:3005, Database:3006, Cache:3007, File Storage:3008.
*   **E2E Шифрование:** V1=WebCrypto+PBKDF2+PIN, V2=Signal Protocol + Premium Secret Chats с AI-фильтром.
*   **Тип документа:** Архитектурное описание V1 (start-release) и V2 (OneYersPlatformRelease). НЕ исходный код, НЕ recovery-гайд.

### 🛠 Рекомендации по E2E

1.  **Не используй TweetNacl** — нет forward secrecy, XSS уязвимость, нет cross-device sync.
2.  **V1: Web Crypto API + PBKDF2 + PIN** — быстрый релиз, XSS защита, достаточно для MVP.
3.  **V2: Signal Protocol (libsignal) + Premium Secret Chats** — industry standard, forward secrecy, AI-фильтр, human review.
4.  **Hybrid approach** — бесшовный переход при первом входе на новое устройство.
5.  **Compliance:** E2E не мешает 152-ФЗ (метаданные видны) и 150-ФЗ (P2P WebRTC для звонков).
6.  **Приоритеты:** Удобство #1, Безопасность #2, Приватность #3.

### 👑 Premium Policies (ФИНАЛЬНОЕ РЕШЕНИЕ)

1.  **Premium Secret Chats** — только для Premium пользователей.
2.  **AI-фильтр** — терроризм, хищения, незаконная торговля, аморальный контент, против сообщества.
3.  **Human review** — 24 часа, агенты ТП (люди).
4.  **Эскалация:** 6=подозрительный, 7=бан 24ч, 8=бан 24ч + 50% штраф, 9=бан + полиция.
5.  **Групповые чаты** — фильтр на ≥50% участников, анонимные жалобы с наградой.
6.  **Запись звонков** — все звонки сохраняются, предупреждение о транскрипции (V3).
7.  **Силовики** — только через ТП, валидация 4 сотрудниками, в рамках закона.

**Никаких изменений по этому вопросу больше не будет.**
