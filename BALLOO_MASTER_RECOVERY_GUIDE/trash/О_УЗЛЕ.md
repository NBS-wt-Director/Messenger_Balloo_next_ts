## 🔑 Ключевые принципы v4.1

### 1. V1/V2 Разделение
- **V1 данные** → остаются в основных разделах (`functions/data.json`, `screens/data.json`, etc.)
- **V2 данные** → переносятся в `deferred_v2/{category}/` подразделы
- **E2E Strategy & Premium Policies** → перенесены в `deferred_v2/e2e_premium/` (v4.1)

### 2. Проблемы (Критично!)
- **Нерешённые проблемы** → `problems/data.json` (только 3 нерешённые: PROB-10, PROB-11, PROB-12)
- **Решённые проблемы** → `resolved_problems/data.json` (9 записей)
- **⛔ Все проблемы решены = ошибка архитектуры!** (должны быть нерешённые)

### 3. Рендеринг
- **On-demand рендер** → разделы рендерятся в момент открытия, не при загрузке
- **Fallback** → при ошибке рендера показывается сообщение об ошибке
- **Embedded JSON** → `app_embedded.js` содержит встроенные данные для работы без сервера

### 4. Naming Policy (канон v3.5)
| Тип | Формат | Пример |
|-----|--------|--------|
| Узел | `node-{slug}` | `node-messenger`, `node-api` |
| Экран | `screen-{node}-{slug}` | `screen-messenger-auth` |
| Компонент | `component-{slug}` | `component-chat-list` |
| Функция | `function-{category}-{slug}` | `function-auth-login` |
| Пакет | `package-{slug}` | `package-core`, `package-ui` |

### 5. Дизайн-система (Ключевое!)
- **🎨 Дизайн-система** → ключевое название, **не менять!**
- Если конфликт с ключевым → записать в **проблемы первым пунктом!**
- Файл: `дизайн-система.md` + `steps/_json/design_system/data.json`

## 🔄 Правила обновления

### Версионирование
- **Каждое изменение = обновление версии** (v4.0 → v4.1 → v4.2...)
- **Версия указывается** в:
  - `О_УЗЛЕ.md` (этот файл)
  - `steps/_json/overview/data.json`
  - `steps/_json/deferred_v2/data.json`

### Обновление данных
1. **MD → JSON (приоритет MD)**
   - Обновляете `.md` файл
   - Синхронизируете в `_json/*/data.json`
   - HTML автоматически подхватывает

2. **JSON → MD (приоритет MD)**
   - Обновляете `_json/*/data.json`
   - Синхронизируете в `.md` файл
   - HTML автоматически подхватывает

### Создание подраздела
1. Создать папку: `steps/_json/{parent}/{subsection}/`
2. Создать `data.json` в новой папке
3. Обновить индекс родителя: добавить в `subsections` массив
4. Обновить `MAPPING.md`: добавить строку в таблицу
5. Обновить `О_УЗЛЕ.md`: добавить в структуру

### Перенос в V2
1. Идентифицировать данные для переноса (по тегу `version: "v2"`)
2. Создать/обновить подраздел в `deferred_v2/{category}/`
3. Обновить статус в оригинале: `"ожидают реализации [дата-время-исполнитель]"`
4. Обновить индекс `deferred_v2/data.json`
