# 1. SERVER-SIDE (PostgreSQL + Drizzle ORM)

**Хранение:** Relational DB (PostgreSQL 16+).  
**ORM:** Drizzle ORM — TypeScript-native, light-weight, генерирует миграции из schema.  
**Принцип:** Type-safe queries без ORM-заглушек. Совместимость с CockroachDB/YugabyteDB.  
**Политика Удаления:** Все данные удаляются мягко (`deleted_at`). Физическое удаление через 10 лет (комплаенс).

  is_favorite BOOLEAN DEFAULT FALSE,
  
  created_at TIMESTAMPTZ DEFAULT NOW(),
  
  UNIQUE(user_id, phone_hash)
);

CREATE INDEX idx_contacts_hash ON contacts(phone_hash);

# 4. ЛОГИКА ХРАНЕНИЯ И УДАЛЕНИЯ (10 Years Rule)

**Требование:** Данные не удаляются физически сразу.

1.  **Мягкое удаление (Soft Delete):**
    *   При удалении чата/сообщения/аккаунта устанавливается `deleted_at = NOW()`.
    *   `is_deleted = TRUE`.
    *   Данные скрыты из UI.

2.  **Архивация (Retention):**
    *   `expires_at` вычисляется как `deleted_at + INTERVAL '10 years'`.
    *   Пример: `expires_at = '2036-06-24'`.

3.  **Физическое удаление (Cron Job):**
    *   Еженедельный бэкенд-скрипт ищет записи: `WHERE expires_at < NOW()`.
    *   Физически удаляет строки из таблиц.

## 2.2 Слой Хранения (Storage Matrix)

| Тип Данных | Хранилище | Безопасность | Описание |
|------------|-----------|--------------|----------|
| **Tokens (JWT)** | `SecureStorage` | 🔴 High | AES-256 шифрование на клиенте. Не перезаписывается при перезагрузке. |
| **E2E Keys** | `SecureStorage` | 🔴 High | Приватный ключ шифрования. Никогда не отправляется на сервер. |
| **UI Settings** | `localStorage` | 🟡 Low | Тема, язык, сортировка чатов. Читаемо пользователем. |
| **User Profile** | `Zustand` (RAM) | 🟡 Low | Кэш профиля. Сбрасывается при logout. |
| **Messages/Chats** | `RxDB` (IndexedDB) | 🟠 Medium | Шифруется через WAL (Write-Ahead Logging) или PouchDB encryption plugin. |
| **Drafts** | `localStorage` | 🟡 Low | Черновики сообщений. |

# 4. СИНХРОНИЗАЦИЯ (SYNC STRATEGY)

**Проблема:** Как синхронизировать `RxDB` (Client) и `PostgreSQL` (Server)?

**Решение:** Conflict-free Replicated Data Types (CRDTs) или Last-Write-Wins (LWW).

1.  **Сообщения:**
    *   Отправка: `RxDB` -> `WebSocket` -> `PostgreSQL`.
    *   Получение: `PostgreSQL` -> `WebSocket` -> `RxDB`.
    *   Конфликт: Невозможен (сообщения immutable).

2.  **Профиль/Настройки:**
    *   Механизм **LWW (Last Write Wins)**.
    *   При обновлении settings на клиенте -> отправляем PATCH на сервер.
    *   При логине -> скачиваем `user.settings` и перезаписываем локальные.

3.  **Аватарки:**
    *   Клиент загружает файл на Яндекс.Диск.
    *   Получает URL.
    *   Отправляет URL на сервер (`PATCH /api/users/me/avatar`).
    *   Сервер обновляет `User.avatar`.

# 5. ХРАНЕНИЕ ФАЙЛОВ (MEDIA STORAGE)

**Решение:** Yandex Disk SDK (объектное хранилище S3-совместимое).

| Тип | Папка в бакете | Логика |
|-----|----------------|--------|
| **Аватары** | `/avatars/{userId}` | Переписываются при смене. Max 5MB. |
| **Фото (Stories)** | `/stories/{userId}/{timestamp}` | Удаляются через 24ч (Cron job). |
| **Файлы (Чаты)** | `/files/{chatId}/{uuid}` | Сохраняются вечно (или по `keepHistory`). |
| **Видео** | `/videos/{chatId}/{uuid}` | Компрессия на клиенте перед загрузкой. |
