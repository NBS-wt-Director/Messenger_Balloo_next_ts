
## 4.2 Отправка сообщения с пересылкой (`POST /api/chats/:id/messages`)

**Request Body (с пересылкой):**
```json
{
  "type": "TEXT",
  "content": "Привет!",

    "from_user_id": "user-uuid-from",
    "message_id": "msg-uuid-orig"
```

# 6. WEBRTC SIGNALING (Calls)

**Протокол:** WebSocket (`ws://api.balloo.su/socket`)

## 6.1 Этапы звонка

1.  **Invite:** `call_invite`
2.  **Answer:** `call_answer`
3.  **Signaling (SDP/ICE):** `call_signaling`
4.  **End:** `call_hangup`

## 6.2 Структура сообщений (JSON)

### `call_invite` (Отправитель)
```json
{
  "type": "call_invite",
  "payload": {
    "chatId": "chat-uuid",
    "type": "VIDEO", // AUDIO, VIDEO
    "offer": {       // SDP Offer (Base64 JSON)
      "sdp": "v=0\r\no=-...",
      "type": "offer"
    }
  }
}
```

### `call_answer` (Ответивший)
```json
{
  "type": "call_answer",
  "payload": {
    "chatId": "chat-uuid",
    "answer": {
      "sdp": "v=0\r\no=-...",
      "type": "answer"
    }
  }
}
```

### `call_signaling` (Обмен ICE candidates)
```json
{
  "type": "call_signaling",
  "payload": {
    "chatId": "chat-uuid",
    "candidate": {
      "candidate": "candidate:...",
      "sdpMid": "0",
      "sdpMLineIndex": 0
    }
  }
}
```

### `call_hangup` (Завершение)
```json
{
  "type": "call_hangup",
  "payload": {
    "chatId": "chat-uuid",
    "reason": "USER_ENDED" // USER_ENDED, NO_ANSWER, FAILED
  }
}
```

# 7. WEBSOCKET EVENTS (Real-time)

**Соединение:** `wss://api.balloo.su/socket`

## 7.1 Подключение

**Client -> Server:**
```json
{
  "type": "connect",
  "payload": {
    "token": "JWT_TOKEN_HERE"
  }
}
```

**Server -> Client:**
```json
{
  "type": "connected",
  "payload": {
    "userId": "user-uuid"
  }
}
```

## 7.2 События

| Событие | Направление | Описание |
|---------|-------------|----------|
| `message_new` | Server -> Client | Новое сообщение (push + local) |
| `message_status` | Server -> Client | Статус (SENT/DELIVERED/READ) |
| `user_typing` | Bidirectional | `user_typing` (chatId), `user_stop_typing` |
| `call_invite` | Server -> Client | Входящий звонок |
| `emergency_alert` | Server -> Client | Экстренное оповещение |
| `story_new` | Server -> Client | Новый сторис от подписки |

# 8. E2E KEY EXCHANGE

**Проблема:** Как клиент Б получает публичный ключ клиента А для шифрования?

**Решение:** Через API профиля.

1.  **Клиент А** генерирует пару RSA/ECDH ключей локально.
2.  **Клиент А** отправляет публичный ключ на сервер:
    `POST /api/users/me/keys`
    ```json
    {
      "publicKey": "-----BEGIN PUBLIC KEY-----\nMIIBIjAN..."
    }
    ```
3.  **Клиент Б** запрашивает профиль А:
    `GET /api/users/A/profile`
4.  **Ответ:** Содержит `publicKey`.
5.  **Клиент Б** шифрует сообщение ключом А и отправляет.

> ⚠️ **Важно:** Приватный ключ никогда не покидает устройство.
