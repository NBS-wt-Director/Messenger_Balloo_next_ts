# 0. ПРАВИЛА ВЕДЕНИЯ ПРОЕКТА (INTEGRITY & STATUS)

## 0.1 Правило Честности (No Lying Policy)

**Запрещено:**
1.  **Врать о статусе реализации.** Если функция не работает — статус `❌ Не реализовано` или `🟡 В работе`. Никогда не ставить `✅ Готово`, если код не написан и не протестирован.
2.  **Скрывать технические долги.** Если есть костыль (workaround) — документировать в `TODO.md` или в комментарии кода.
3.  **Фальсифицировать тесты.** Тесты должны проверять реальную функциональность, а не быть "для галочки".
4.  **Игнорировать ошибки.** Если сборка падает — фиксировать ошибку, а не обходить её отключением теста.

**Наказание за нарушение:**
- Пересмотр архитектуры.
- Аудит кода независимым разработчиком.
- Публичное признание ошибки в changelog.

## 0.2 Автоматическое Обновление Статусов

**Правило:** После реализации каждой функции статус в документации обновляется **автоматически** (через CI/CD хук или вручную ответственным разработчиком).

**Статусы:**
| Статус | Значение | Цвет |
|--------|----------|------|
| `🟡 ПЛАНИРОВАНИЕ` | Функция описана, код не писан | Жёлтый |
| `🔵 В РАБОТЕ` | Код пишется, ветка активна | Синий |
| `🟠 CODE REVIEW` | Код готов, ждет проверки | Оранжевый |
| `✅ ГОТОВО` | Код принят, тесты пройдены | Зелёный |
| `❌ ОТКЛОНЕНО` | Функция не нужна / отменена | Красный |

**Инструкция для исполнителя:**
1.  Завершил задачу → Запустил тесты → Убедился, что всё работает.
2.  Открыл документацию → Нашел функцию → Сменил статус на `✅ ГОТОВО`.
3.  Добавил дату реализации и ссылку на PR/Commit.
4.  **Запрещено** менять статус без прохождения тестов.

export function useAprilFools() {
  const isAprilFirst = new Date().getDate() === 1 && new Date().getMonth() === 3;
  
  const jokeLanguages = ['soviet', 'imperial', 'tsar', 'galactic'];
  const currentYear = new Date().getFullYear();
  const yearOffset = (currentYear - 2026) % 4;  // Цикл с 2026
  const currentJokeLang = jokeLanguages[yearOffset];
  
  return {
    isEnabled: isAprilFirst,
    activeLanguage: isAprilFirst ? currentJokeLang : null
  };
}

### 🚨 Строка Экстренного Оповещения (Emergency Bar)

**Статус:** 🟡 Планируется (v1: ручная, v2: AI)  
**Расположение:** Под Header (`<EmergencyBar />`), full-width, sticky top  
**Default:** Скрыто (`display: none` / `hidden`)  

#### Логика работы
- **Источник:** Боты силовых ведомств (Полиция, МЧС, Армия, Медики)
- **Доступ к ботам:** Только по разрешению администраторов (выдача прав через админ-панель)
- **Группировка получателей (v1):** Ручные списки в админке (привязка групп/регионов к ботам)
- **Группировка получателей (v2):** AI-анализ групп, подписок и чатов для определения региона/интересов пользователя
- **Триггер:** WebSocket событие `emergency_alert` или polling
- **Отображение:** Полоса на всю ширину под хедером, цвет зависит от уровня угрозы (красный/жёлтый/синий)
- **Поведение:** 
  - При появлении — slide-down анимация
  - Требует подтверждения/закрытия пользователем
  - Скрывается по умолчанию, показывается только при активных оповещениях

#### UI/UX Спецификация
```
┌────────────────────────────────────────────────────────────┐
│ 🚨 ЭКСТРЕННОЕ ОПОВЕЩЕНИЕ: Уровень 3 (Жёлтый)               │
│ 📍 Регион: Москва и МО  |  🕒 14:30  |  [✓] [✕]           │
└────────────────────────────────────────────────────────────┘
```
- **Высота:** 48px (collapsed), 72px (expanded with details)
- **Цветовая кодировка:**
  - 🔴 Красный: Максимальная угроза (военное положение, теракт)
  - 🟡 Жёлтый: Повышенная угроза (ЧС, паводок, эвакуация)
  - 🔵 Синий: Информационное (погода, дорожные работы)
- **Кнопки:** `[✓] Подтвердить` (закрыть), `[✕] Подробнее` (открывает модалку с деталями)
- **Детали (модалка):** Исходное сообщение, время, регион, инструкции, ссылка на официальный источник

#### Интеграция с Backend
- **Endpoint:** `GET /api/emergency/status` (polling fallback)
- **WebSocket:** `emergency_alert` event
- **Auth:** Bot tokens signed by admin, validated on client via JWT claims
- **Rate Limit:** 1 alert per region per 15 min (anti-spam)

| **File Storage** | `services/media-server/` | Обработка медиа | 3008 |

# 7. CI/CD И ДЕПЛОЙ

## 7.1 GitHub Actions Pipeline

```yaml
name: Balloo CI/CD
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v3
      - run: pnpm install
      - run: pnpm lint

  test:
    runs-on: ubuntu-latest
    needs: lint
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v3
      - run: pnpm install
      - run: pnpm test

  build:
    runs-on: ubuntu-latest
    needs: test
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v3
      - run: pnpm install
      - run: pnpm build

  deploy:
    runs-on: ubuntu-latest
    needs: build
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      - run: ./deploy.sh
```
