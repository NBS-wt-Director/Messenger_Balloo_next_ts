# 1. АУТЕНТИФИКАЦИЯ И СЕССИИ

## 1.1 Токены (JWT)
*   **Access Token:**
    *   Срок жизни: 15 минут.
    *   Хранение: `SecureStorage` (Mobile) / `HttpOnly Cookie` (Web).
    *   Тип: `RS256` (RSA Signature) для распределенных систем или `HS256` для монолита.
*   **Refresh Token:**
    *   Срок жизни: 30 дней.
    *   Хранение: `SecureStorage` (HttpOnly, SameSite=Strict).
    *   Вращение: При каждом использовании генерируется новый Refresh Token, старый инвалидируется.

## 1.2 Пароли
*   **Хеширование:** `Argon2id` (предпочтительно) или `bcrypt` (cost factor >= 12).
*   **Политика сложности:** Мин 8 символов, закомментировано по умолчанию (для удобства), но доступно в настройках.
*   **Brute-force защита:**
    *   Lockout после 5 неудачных попыток.
    *   Exponential backoff (1s, 2s, 4s...).
    *   CAPTCHA после 10 попыток.

## 1.3 Двухфакторная аутентификация (2FA)
*   **TOTP (Time-based One-Time Password):** RFC 6238 (Google Authenticator, Authy).
    *   QR-код генерируется на клиенте, сохраняется в профиль.
    *   Secret key шифруется на сервере (AES-256-GCM).
*   **SMS (Android Nodes / Max Server):**
    *   Rate limit: 3 SMS / час.
    *   Защита от SIM-swap: Анализ IP-адреса и геолокации при входе с нового устройства.

# 2. END-TO-END ENCRYPTION (E2EE)

**Принцип:** Сервер не может прочитать содержимое сообщений.

## 2.1 Алгоритмы
*   **Ключи:** Curve25519 (ECDH) для обмена ключами.
*   **Шифрование:** AES-256-GCM (Authenticated Encryption).
*   **Хеш:** SHA-256.

## 2.2 Обмен ключами (Key Exchange)
1.  **Генерация:** При регистрации клиент генерирует пару `Private/Public Key` локально.
2.  **Хранение:**
    *   `PrivateKey`: Никогда не покидает устройство (SecureStorage).
    *   `PublicKey`: Отправляется на сервер и хранится в профиле пользователя (`users.public_key`).
3.  **Шифрование:**
    *   Отправитель получает `PublicKey` получателя.
    *   Генерирует `Session Key` (AES).
    *   Шифрует сообщение `Session Key` публичным ключом получателя (для передачи ключа).
    *   Шифрует `Payload` симметричным `Session Key`.
4.  **Хранение на сервере:**
    *   Поле `messages.payload` хранит Base64 строку: `[EncryptedSessionKey][IV][Ciphertext][Tag]`.

## 2.3 Сессии (Signal Protocol Style — Future)
Для высокой безопасности групповых чатов планируется реализация Double Ratchet Algorithm (как в Signal/WhatsApp).

# 3. БЕЗОПАСНОСТЬ ДАННЫХ

## 3.1 Transmission (In Transit)
*   **TLS:** Версия 1.3 (обязательно).
*   **HSTS:** Strict-Transport-Security (max-age=31536000).
*   **CORS:** Строгая политика (Allow-Origin: specific domains only).

## 3.2 Storage (At Rest)
*   **База данных:**
    *   `users.password` (hash) — зашифрован алгоритмом хеширования.
    *   `users.2fa_secret` — зашифрован AES-256-GCM ключом приложения.
    *   `messages.payload` — зашифрован E2E ключами пользователей.
*   **Файловое хранилище (Yandex Disk):**
    *   Превью аватаров/фото не содержат PII (удаление EXIF данных при загрузке).
    *   Ссылки на файлы (Signed URLs) действуют ограниченное время.

# 4. ЗАЩИТА ОТ АТАК (OWASP)

## 4.1 SQL Injection (SQLi)
*   **Правило:** Полный запрет на конкатенацию строк в SQL.
*   **Реализация:**
    *   Использование `node-postgres` (`pg`) с параметризированными запросами.
    *   Пример: `SELECT * FROM users WHERE id = $1` (вместо `WHERE id = '${id}'`).
    *   Использование Kysely (Type-safe SQL builder).

## 4.2 Cross-Site Scripting (XSS)
*   **CSP (Content Security Policy):**
    *   `default-src 'self';`
    *   `script-src 'self';` (запрет inline-скриптов).
    *   `style-src 'self' 'unsafe-inline';` (для Tailwind/Styled-components).
*   **Санитизация:**
    *   Ввод пользователей (bio, messages) хранится как есть, но выводится через экранирование (React делает это автоматически).
    *   Markdown парсер (для сообщений) должен иметь whitelist тегов (no `<script>`, no `<iframe>`).

## 4.3 CSRF (Cross-Site Request Forgery)
*   **Cookies:** `SameSite=Strict` или `Lax`.
*   **Tokens:** Использование CSRF tokens для форм (если есть).

## 4.4 Rate Limiting
*   **Global:** 1000 req/min (IP based).
*   **Auth:** 10 req/min (per IP) на login/register.
*   **SMS:** 3 req/hour (per phone).
*   **API:** 100 req/min (per user token).
*   **Инструмент:** `express-rate-limit` + Redis.

# 5. КЛИЕНТСКАЯ БЕЗОПАСНОСТЬ

## 5.1 Хранение чувствительных данных
*   **Токены:** `SecureStorage` (Android Keystore / iOS Keychain).
*   **E2E Keys:** `SecureStorage`.
*   **Local Storage:** Только UI настройки (тема, язык).

## 5.2 Защита от отладки
*   **Mobile:**
    *   Проверка на Root (Android) / Jailbreak (iOS).
    *   Блокировка работы при обнаружении эмулятора/отладчика.
    *   Запрет на создание дампa памяти (`FLAG_SECURE` на Android).

## 5.3 Биометрия
*   Вход по FaceID / TouchID / Android BiometricPrompt.
*   Биометрия разблокирует `SecureStorage` с ключами.

# 6. БЕЗОПАСНОСТЬ БОТОВ (EMERGENCY ALERTS)

## 6.1 Аутентификация ботов
*   **Token:** JWT с особым claims (`role: EMERGENCY_BOT`, `issuer: ADMIN`).
*   **IP Whitelisting:** Сервер принимает запросы на `/api/emergency` только с доверенных IP адресов ведомств.

## 6.2 Валидация
*   Проверка `region_id` (соответствует ли регион полномочиям бота).
*   Rate Limiting: 1 alert per region per 15 minutes.

# 7. КОМПЛАЙЕНС И ПРАВА ПОЛЬЗОВАТЕЛЯ

## 7.1 Удаление аккаунта (Right to be Forgotten)
*   **Soft Delete:** Пользователь помечается `is_deleted = true`.
*   **Data Sanitization:**
    *   `email`, `phone`, `displayName`, `bio` очищаются (генерируются псевдонимы).
    *   `public_key` удаляется.
    *   Личные сообщения (payload) удаляются физически или перепривязываются к анонимному пользователю.
*   **GDPR / 152-ФЗ:**
    *   Хранение данных на серверах в стране юрисдикции пользователя (или РФ для RU).
    *   Возможность экспорта данных (JSON).

## 7.2 Journaling / Audit Log
*   **Таблица:** `audit_logs` (Write-Only).
*   **События:**
    *   `LOGIN_SUCCESS`, `LOGIN_FAILED`.
    *   `SETTINGS_CHANGE`.
    *   `2FA_ENABLE/DISABLE`.
    *   `ADMIN_ACTION` (Ban, Alert Send).
*   **Хранение:** 90 дней.
